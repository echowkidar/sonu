# SONU — architecture contract (step 1 and 1b)

Binding for everyone who writes code in this repository. Design sources (outside the repo, read-only):
`..\design\*.md`, `..\analysis\*.md`. This repo must never contain secrets, real exports or personal data.

## Layout — independent npm packages (no root workspace, each has its own `node_modules` and lockfile)

| Folder | Package | Content |
|---|---|---|
| `packages/core` | `@sonu/core` | Pure TypeScript, no database, no network: XLS/XLSX reading, Marafiq export parsers, tracker-workbook loader, computed columns, deadline rules, status suggestions, mirror diff → events, bulk-import template parsing/validation, RFE writer, Master workbook writer, synthetic fixtures. |
| `server` | `@sonu/server` | Fastify 5 API + static hosting of the built web app, PostgreSQL (`pg`, plain SQL migrations in `server/migrations/NNN_name.sql`), scheduler. Depends on core via `"@sonu/core": "file:../packages/core"`. |
| `web` | `@sonu/web` | Vite + React + TypeScript + Tailwind + shadcn/ui, TanStack Query/Table/Virtual, Recharts, lucide icons, `motion`; PWA via `vite-plugin-pwa` (injectManifest, own service worker with push handler). Built output is served by the server. |
| `worker` | `@sonu/worker` | Playwright worker for the optional Marafiq connection + `worker/mock-portal` used by tests. No database access. |
| `assets` | — | RFE template, tracker lookups, three bulk-import templates (run-time files). |
| `fixtures` | — | Synthetic export files with exact captions and fictional data (generated by a script in core). |

Language: TypeScript (ESM, `strict`), Node 22 LTS in Docker (local machine has Node 26 — code must run on both). Tests: `vitest`. Validation: `zod`. No ORM.

## Tenancy, roles, auth

- Every business table has `contractor_id`. Every query goes through functions that take the caller's `contractor_id`; no route reads another contractor's rows. Tests must prove isolation.
- Roles: `platform_admin` (no contractor, cannot see work data), `contractor_admin`, `manager`, `coordinator`, `purchasing`, `supervisor`, `foreman`, `technician`. Work teams (zones) scope supervisors/foremen/technicians; coordinator, manager, contractor admin see all of their contractor.
- Login name = e-mail. Accounts only by invitation or bulk import; invite link (single-use, hashed token, expiry) verifies the address and sets the password. No self-registration.
- Passwords: Node `crypto.scrypt` (no native add-ons). Sessions: random token in an `httpOnly`, `SameSite=Lax` cookie, hash stored in `session` table; `Secure` when the request is https (honour `TRUST_PROXY=1`: `X-Forwarded-Proto`, `CF-Connecting-IP`). Mutating routes require header `X-Requested-With: sonu` (CSRF). Login is rate-limited per IP and per e-mail.
- First start with no users: the server prints a one-time setup code to its log; `/setup` + that code creates the platform admin. No default password anywhere.
- Audit log row for every create / change / import / export / sign-in / connection use.

## Secrets

- `ENCRYPTION_KEY` (env, 32 bytes base64) — AES-256-GCM. Table `secret(id, contractor_id, purpose, ciphertext, iv, tag, key_version, updated_at)`. Other tables hold only `secret_id`.
- No API response, log line, audit row or export ever contains a stored secret. Forms are write-only: the API returns `hasPassword: true/false`. Bulk Excel import rejects any column that looks like a password.
- VAPID keys for web push are generated on first start and stored in the database (private key encrypted).

## Data flow of imports (manual upload and worker use the same path)

`file → core.readSheet → core.detectExport(captions) → core.parse<Export>() → rows` — all-or-nothing: a missing caption fails the whole file with the caption named and nothing loaded. Then the server, in one transaction: `import_batch` row (file name, type, user or sync run, hash, counts) → upsert mirror tables → `core.diffMirror(before, after)` → events (`wr.seen`, `wr.changed`, `wr.gone`, `wr.stage_changed`, `rfe.approved`, `rfe.returned`, `rfe.comment_received`, `ptw.changed`, `ptw.expiring`, `money.changed`) → `wr_stage_history` / timeline → notifications. SONU-owned columns (owner, criterion, contractor status, remarks) are never overwritten by an import. "Marafiq data as of" = time of the last successful import per list.

Computed columns (age bucket, Days to Breach, TD Status, KPI, RFE status, RFE time frame, discipline, facility, zone) are computed by core at read time with "today" in the contractor's time zone (default `Asia/Qatar`); they are not stored.

## Internal worker API (server ⇄ worker, only on the compose network)

- Auth: `Authorization: Bearer <token>`, token = hex(HMAC-SHA256(key = ENCRYPTION_KEY bytes, "sonu-worker-v1")). The server refuses `/internal/*` when the request carries `X-Forwarded-For`, `CF-Connecting-IP` or `CF-Ray` (i.e. came through the tunnel).
- `GET /internal/worker/jobs/next` → `204` or `{ jobId, kind: "test" | "sync", connection: { id, baseUrl, project, username, password }, lists: string[] }` (list keys). The server never hands out a job while the connection is paused, off, or in `needs_attention`.
- `POST /internal/worker/jobs/:jobId/file` multipart `{ listKey, file }` → `{ ok, rowsRead, error? }` (server runs the normal import path).
- `POST /internal/worker/jobs/:jobId/result` `{ status: "ok" | "signin_failed" | "error", signInAttempts, lists: [{ key, ok, rows?, error? }], message? }`. On `signin_failed` the server sets the connection to `needs_attention`, alerts the contractor admin, and creates no further jobs until the admin saves the password again or presses Resume.
- The worker polls every 15 s. The schedule lives in the server. The list-key → view-address allow-list is hard-coded in the worker; unknown keys are ignored.

## Ports and environment

Container port 3000. Env: `DATABASE_URL` (compose builds it from `POSTGRES_PASSWORD`), `ENCRYPTION_KEY`, `PUBLIC_URL`, `SONU_PORT` (host port, default 8091), `TRUST_PROXY`, `UPLOAD_DIR` (default `/data/uploads`), `NODE_ENV`. Health: `GET /api/health`. All API routes under `/api`.
